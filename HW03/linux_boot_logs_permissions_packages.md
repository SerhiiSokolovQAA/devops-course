# Linux: завантаження, журнали, права доступу, менеджери пакетів

## 1. Етапи завантаження системи Linux

Від натискання кнопки живлення до запрошення входу система проходить шість етапів.

### 1.1. BIOS / UEFI

- Після ввімкнення процесор виконує код прошивки материнської плати — **BIOS** (старі
  системи) або **UEFI** (сучасні).
- Виконується **POST** (Power-On Self-Test) — перевірка процесора, пам'яті, дисків та
  іншого обладнання.
- Прошивка шукає завантажувальний пристрій за порядком, заданим у налаштуваннях
  (диск, USB, мережа).
- BIOS читає перший сектор диска — **MBR** (512 байт). UEFI читає завантажувач з
  окремого розділу **EFI System Partition (ESP)** (файли `.efi`, таблиця розділів **GPT**).

### 1.2. Завантажувач (Bootloader) — GRUB2

- Найпоширеніший завантажувач — **GRUB2** (інші: systemd-boot, LILO, syslinux).
- Показує меню вибору ОС або версії ядра (налаштування в `/boot/grub/grub.cfg`,
  редагуються через `/etc/default/grub` і `update-grub`).
- Завантажує в пам'ять **ядро** (`/boot/vmlinuz-...`) та **initramfs**
  (`/boot/initrd.img-...`) і передає ядру параметри командного рядка
  (наприклад, `root=/dev/sda2 ro quiet`).

### 1.3. Ядро (Kernel)

- Ядро розпаковується, ініціалізує процесор, пам'ять, планувальник процесів.
- Виявляє обладнання і завантажує вбудовані драйвери.
- Монтує **initramfs** як тимчасову кореневу файлову систему.

### 1.4. initramfs (initial RAM filesystem)

- Це маленька тимчасова файлова система в оперативній пам'яті з мінімальним набором
  драйверів і скриптів.
- Її завдання — підготувати доступ до справжнього кореневого розділу: підвантажити
  драйвери диска, зібрати RAID/LVM, розшифрувати LUKS-розділ тощо.
- Після цього справжній корінь `/` монтується, і керування переходить до нього
  (`switch_root`).

### 1.5. Процес init — systemd (PID 1)

- Ядро запускає першу програму простору користувача — **init**. У сучасних дистрибутивах
  це **systemd** (раніше — SysV init, Upstart). Він має ідентифікатор процесу **PID 1** і є
  предком усіх інших процесів.
- systemd читає свої налаштування (юніти) і запускає служби паралельно з урахуванням
  залежностей: монтування файлових систем (`/etc/fstab`), мережа, журналювання, SSH,
  cron, веб-сервер тощо.
- Цільовий стан системи задається **target**:
  - `multi-user.target` — текстовий багатокористувацький режим (аналог runlevel 3);
  - `graphical.target` — з графічним інтерфейсом (аналог runlevel 5);
  - `rescue.target` — режим відновлення (аналог runlevel 1).
- Переглянути поточну ціль: `systemctl get-default`.

### 1.6. Вхід користувача

- Запускається **getty** (вхід у текстовій консолі) або **display manager**
  (GDM, LightDM, SDDM — графічний вхід), а на серверах — ще й `sshd` для віддаленого входу.
- Після введення логіна й пароля запускається оболонка користувача (`bash`) або графічне
  середовище. Система готова до роботи.

### Коротка схема

```
Живлення -> BIOS/UEFI (POST) -> GRUB2 -> Ядро -> initramfs -> systemd (PID 1) -> targets/служби -> вхід
```

Корисні команди: `systemd-analyze` (скільки тривало завантаження),
`systemd-analyze blame` (які служби завантажувалися найдовше), `dmesg` (повідомлення ядра
під час завантаження).

## 2. Як переглянути системні журнали

У Linux є два основні механізми журналювання: **journald** (частина systemd, двійковий
журнал) і класичний **syslog** (rsyslog, текстові файли в `/var/log`).

### 2.1. journalctl (журнал systemd)

| Команда | Що показує |
|---|---|
| `journalctl` | увесь журнал (від найстаріших записів) |
| `journalctl -r` | у зворотному порядку (найновіші зверху) |
| `journalctl -f` | стежить за журналом у реальному часі (як `tail -f`) |
| `journalctl -n 50` | останні 50 записів |
| `journalctl -b` | записи з поточного завантаження |
| `journalctl -b -1` | записи з попереднього завантаження |
| `journalctl --list-boots` | список усіх завантажень |
| `journalctl -u nginx.service` | записи конкретної служби |
| `journalctl -k` | лише повідомлення ядра |
| `journalctl -p err` | лише помилки (рівні: emerg, alert, crit, err, warning, notice, info, debug) |
| `journalctl --since "2026-10-01 10:00" --until "1 hour ago"` | записи за проміжок часу |
| `journalctl _PID=1234` | записи конкретного процесу |
| `journalctl --disk-usage` | скільки місця займає журнал |

Ключі можна поєднувати, наприклад: `journalctl -u ssh -b -p warning -f`.

### 2.2. Текстові журнали в /var/log

| Файл | Вміст |
|---|---|
| `/var/log/syslog` (Debian/Ubuntu) або `/var/log/messages` (RHEL/CentOS) | загальні системні повідомлення |
| `/var/log/auth.log` (Debian/Ubuntu) або `/var/log/secure` (RHEL) | входи, `sudo`, SSH, автентифікація |
| `/var/log/kern.log` | повідомлення ядра |
| `/var/log/dmesg` | повідомлення ядра під час завантаження |
| `/var/log/boot.log` | хід завантаження служб |
| `/var/log/dpkg.log`, `/var/log/apt/history.log` | встановлення і видалення пакетів |
| `/var/log/nginx/`, `/var/log/apache2/` | журнали веб-серверів |

Переглядати їх можна звичайними утилітами:

```bash
sudo less /var/log/syslog          # гортати файл
sudo tail -n 100 /var/log/auth.log # останні 100 рядків
sudo tail -f /var/log/syslog       # стежити в реальному часі
sudo grep -i error /var/log/syslog # шукати помилки
zcat /var/log/syslog.2.gz | less   # старі стиснуті журнали
```

### 2.3. Інші корисні команди

- `dmesg` або `dmesg -T` (з читабельним часом) — кільцевий буфер повідомлень ядра.
- `last` — історія входів у систему, `lastb` — невдалі спроби входу.
- `who`, `w` — хто зараз у системі.

Старі журнали автоматично архівуються і видаляються службою **logrotate**
(налаштування в `/etc/logrotate.conf` і `/etc/logrotate.d/`).

## 3. Дозвіл `-rw-------`: опис і як додати право на виконання

### 3.1. Як читати рядок прав

Рядок із 10 символів розбивається так:

```
 -    rw-    ---    ---
 |     |      |      |
 |     |      |      +-- інші (others)
 |     |      +--------- група (group)
 |     +---------------- власник (user/owner)
 +---------------------- тип файлу
```

- 1-й символ — тип: `-` звичайний файл, `d` каталог, `l` символьне посилання.
- Далі три трійки: `r` — читання (4), `w` — запис (2), `x` — виконання (1),
  `-` — права немає.

### 3.2. Що означає `-rw-------`

| Частина | Значення |
|---|---|
| `-` | звичайний файл |
| `rw-` | **власник** може читати й змінювати файл, але не виконувати |
| `---` | **група** не має жодних прав |
| `---` | **інші** не мають жодних прав |

У числовому вигляді це **600** (власник: 4+2=6, група: 0, інші: 0).

Такий дозвіл ставлять на приватні файли, доступ до яких має лише власник: приватні
SSH-ключі (`~/.ssh/id_rsa` — SSH навіть відмовиться працювати з ключем, якщо права
ширші), файли з паролями, `.env`, `~/.bash_history`. Користувач `root` все одно має доступ.

### 3.3. Як додати право на виконання

Команда `chmod` (change mode):

```bash
chmod u+x file.sh   # виконання лише для власника   -> -rwx------ (700)
chmod +x file.sh    # виконання для всіх (з урахуванням umask) -> -rwx--x--x (711)
chmod a+x file.sh   # явно для всіх: власник, група, інші -> -rwx--x--x (711)
chmod 700 file.sh   # те саме, що u+x, у числовому вигляді
```

Символьний запис: `u` — власник, `g` — група, `o` — інші, `a` — всі; `+` додати,
`-` прибрати, `=` встановити точно.

Для файлу `-rw-------` найлогічніше `chmod u+x file` — файл залишиться приватним, але
власник зможе його запускати. Перевірити результат: `ls -l file`. Запустити скрипт:
`./file.sh`.

## 4. Різниця між apt і dpkg

Обидва інструменти керують пакетами `.deb` у Debian, Ubuntu та похідних дистрибутивах,
але працюють на різних рівнях.

- **dpkg** (Debian Package) — низькорівневий інструмент. Встановлює, видаляє і показує
  інформацію про **локальні** `.deb`-файли. Залежностей не вирішує й нічого з інтернету
  не завантажує.
- **apt** (Advanced Package Tool) — високорівневий менеджер, який працює **поверх dpkg**.
  Сам завантажує пакети з репозиторіїв, автоматично знаходить і встановлює залежності,
  оновлює систему. Для власне встановлення він викликає dpkg.

### Порівняння

| Ознака | dpkg | apt |
|---|---|---|
| Рівень | низький | високий (використовує dpkg) |
| Джерело пакетів | лише локальний `.deb`-файл | репозиторії з `/etc/apt/sources.list` і `/etc/apt/sources.list.d/` |
| Завантаження з інтернету | ні | так |
| Залежності | не вирішує: при нестачі видає помилку | знаходить і встановлює автоматично |
| Оновлення всієї системи | ні | так (`apt upgrade`) |
| Пошук пакетів | лише серед встановлених (`dpkg -l`) | у репозиторіях (`apt search`) |
| Типове використання | ручне встановлення окремого `.deb`, перегляд вмісту пакета | щоденне встановлення й оновлення програм |

### Приклади команд

dpkg:

```bash
sudo dpkg -i package.deb   # встановити локальний пакет
sudo dpkg -r package       # видалити пакет (залишити налаштування)
sudo dpkg -P package       # видалити разом із налаштуваннями
dpkg -l                    # список встановлених пакетів
dpkg -L package            # які файли встановив пакет
dpkg -S /usr/bin/ls        # якому пакету належить файл
```

apt:

```bash
sudo apt update                 # оновити список пакетів з репозиторіїв
sudo apt upgrade                # оновити встановлені пакети
sudo apt install nginx          # встановити пакет разом із залежностями
sudo apt remove nginx           # видалити пакет
sudo apt purge nginx            # видалити разом із налаштуваннями
sudo apt autoremove             # прибрати непотрібні залежності
apt search nginx                # шукати пакет
apt show nginx                  # інформація про пакет
sudo apt install ./package.deb  # встановити локальний .deb і докачати залежності
```

Типова ситуація: після `sudo dpkg -i package.deb` з'являється помилка про відсутні
залежності — її виправляє `sudo apt -f install` (apt докачує те, чого бракує).

**Висновок:** dpkg — це «фундамент», який уміє лише розпакувати й встановити конкретний
файл; apt — зручна надбудова, яка сама знаходить, завантажує і встановлює пакети з усіма
залежностями.
